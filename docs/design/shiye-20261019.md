# 拾页：笔记与日记

以 Jiaoban main `4e704c622481f5d2d55961336c183573dfd7abcb` 为基线。显示名候选「拾页」表达收起想法与日常的一页；不主张商标独占。应用 ID cn.jiaoban、存储文件、更新仓库/资产前缀和原签名覆盖升级链路保留。

## 实现

首页是无标题正文时间流。单层浅纸卡片、低饱和苔绿，正文优先、日期弱化。底部仅记录/日记；不铺统计、积分、等级或待办勾选。日记按选择的日期展示独立小结，编辑可补记旧日期；当天碎片仅折叠参考，同日旧日记全部保留，不复制也不级联操作。阅读保留完整可选文本；原清单字符串按原文显示，不再提供勾选任务功能。

新日记继续保存为 NOTE，另带可选 journalDate，避免旧读者把新类型误认为交办。普通旧笔记仍无日期。旧 TODO/DELEGATED 的 ID、原文、来源、期限策略、状态、步骤和进展不迁移、不清理，只从设置只读打开。完整 ZIP 通过系统文件选择器保存并可恢复缺少的记录与附件；支持范围见 [导入说明](import-formats.md)。旧版本重新保存会丢掉不认识的 journalDate，禁止建议降级。

## 随手记录交互

本轮采用类似 flomo 的低摩擦记录方式：无必填标题、正文优先的倒序时间流；底部直接输入和一次“记下”，不先选分类。旧标题仍是原文，不拆字段或重写旧数据。记录页仅展示没有 journalDate 的碎片；日记页展示有 journalDate 的独立小结；已有日记的指定日期保留。单级 #标签支持中文、换行与重复去重，网址 fragment 不识别；标签可点选并清除筛选。手动回顾仅从本机未归档、早于今天的记录挑选，不注入虚构记录。

公开交互参考（独立原创实现，不复制品牌或代码）：
- flomo 官方快速记录：https://help.flomoapp.com/basic/quick-input.html
- 官方标签：https://help.flomoapp.com/basic/tag.html（其多级标签不在本轮范围）
- 官方回顾：https://help.flomoapp.com/advance/lucky.html（本轮仅本地手动回顾）
- Memos：https://github.com/usememos/memos，MIT，无标题时间流参考，不引入服务器。
- MoeMemos Android：https://github.com/mudkipme/MoeMemosAndroid，GPL-3.0，仅参考交互。当前版本支持本地存储与备份，不要求服务器；不移植其代码。

快捷草稿写入私有 SharedPreferences，切页、看详情、重建后恢复；存盘成功才清空。稳定请求 ID 防止重试重复，旧回调核对 ID/正文后才能清稿。写失败保留草稿并提示重试。全屏日记/分享编辑也改为成功后关闭。调试验收 fixture 均为合成内容，不进入生产默认数据。

### 保存与重建边界

- 每个数据库路径在进程中只有一个 TasksHolder，无 Activity 引用；主题/Activity 重建复用它的 IO 序列与状态。
- 待提交操作与已落盘快照分开。UI 读取 savedTasks；每次操作的差异在单写队列中应用到最新磁盘快照。失败的正文不会夹带到下一条独立保存；失败的文字仍留在草稿。
- 快捷草稿按稳定 ID 重试，SharedPreferences 监听保证旧页面保存完成后新页面也同步清稿。
- 全屏编辑拥有独立会话 ID、持久正文/日期/新记录 ID。在途状态跨 Activity 重建保留，真进程重启解除过期等待；完成回调核对会话、正文、日期，只能清自己的草稿。新分享不能替换仍在保存的会话。
- 明确放弃编辑仅清该编辑草稿；失败的编辑不能在下一次保存中复活。测试通过 IO 队列闸门制造在途重建，并通过临时文件阻塞制造落盘失败。

## 记录与日记的不同任务

随手记录用于即时捕捉，日记用于一天的独立回想。没有碎片也能写日记，不先要求心情、标题或长文；未保存就不生成空日记。日期选择使用 Material3 DatePicker；当天碎片作为可选参考，不自动拼接或复制。日期只建立查看关联，没有父子数据或级联删除。

参考 [flomo 日历](https://help.flomoapp.com/advance/notes-graph.html) 的检索边界、[StoryPad](https://github.com/theachoem/storypad)（GPL-3.0）的日记体验与 [Daily You](https://github.com/Demizo/Daily_You)（GPL-3.0，附加条款）的每日记录概念，只借交互，不移植代码或素材。

## 应用内更新的恢复与确认

沿用固定私有 GitHub 仓库和既有设备授权，不扩大仓库权限。进入应用仅核对本机缓存，不自动联网或下载；检查、下载和系统安装均由用户点击。更新状态由 application 级 owner 持有，离页和 Activity 重建继续观察同一下载。进程退出后，已完成下载的公开校验元数据可恢复，必须重新核对字节、包名、版本及签名；未完成下载不冒充续传，提示手动重试。

安装前再做一次完整校验，验证期间重复点击不重复启动安装。缺少安装权限时明确引导用户打开系统设置，返回后再次点继续；最终仍由系统安装器确认。取消授权与迟到授权写入同步，取消后不持久化新授权。清除授权不删除已校验安装包，原有记录不参与更新器操作。缓存与更新元数据不进入主动 ZIP 或系统备份。
